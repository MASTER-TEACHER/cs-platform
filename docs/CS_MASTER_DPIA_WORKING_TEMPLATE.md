# CS Master — DPIA Working Template

Status: working template for completion with the relevant school/data controller.

## 1. Processing being assessed
Describe CS Master deployment, user groups, schools, features enabled, data flows and any AI-supported functions.

## 2. Purpose and necessity
For each processing activity record: purpose, data fields, users affected, lawful basis selected by the controller, necessity and less-intrusive alternatives considered.

## 3. Children and vulnerable users
Record age range, transparency measures, default settings, profiling/analytics, teacher oversight, safeguarding implications and how unnecessary collection is prevented.

## 4. Data flows and processors
Document browser/app → Firebase/Auth/Firestore/Storage → server routes → configured providers (for example AI, hosting, email and payments), including regions/transfers and contractual safeguards.

## 5. Risk assessment
For each risk record likelihood, severity, affected people, existing controls, additional controls, owner, deadline and residual risk.

Suggested risks: cross-school disclosure; excessive teacher/admin access; compromised account; exposed API secret; inappropriate AI prompt content; inaccurate automated feedback; retention beyond need; accidental deletion; assessment-integrity misuse; service-provider incident.

## 6. Consultation and sign-off
Record school DPO/leadership consultation, pupil/parent transparency considerations, technical review, residual high risks and final approval.
