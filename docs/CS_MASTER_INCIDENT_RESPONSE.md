# CS Master — Security / Personal Data Incident Response

1. Contain: disable affected credentials/routes/accounts and preserve evidence.
2. Assess: what happened, data/schools/users affected, start/end time, access/exfiltration risk.
3. Notify internal owner/DPO contact and affected school controller promptly.
4. Determine regulatory notification requirements and deadlines with the controller/DPO; document the decision.
5. Remediate the technical cause, rotate exposed credentials and validate tenancy/authorization.
6. Communicate accurately to affected users where required; do not speculate.
7. Record timeline, decisions, evidence, remediation and follow-up actions.
8. Run a post-incident review and add regression tests/monitoring for the failure mode.

Never place service-account keys, passwords, payment details or full sensitive records in ordinary support tickets.
