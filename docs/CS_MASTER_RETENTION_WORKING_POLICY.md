# CS Master — Retention Working Policy

This file defines the implementation questions that must be agreed before automatic deletion jobs are enabled. Do not invent one universal retention period for every school record.

- Account/profile: retain while account is active; define post-closure period.
- School membership: retain only while required for access/audit; define historical membership requirement.
- Class membership: archive class history rather than deleting active educational records accidentally.
- Assignments/submissions/results: school/controller to define educational retention requirement.
- Exam integrity incidents: define assessment/audit retention separately.
- AI prompts/responses: minimise personal data and define a short, explicit retention purpose where stored by CS Master.
- Feedback reports: retain until resolved plus an agreed operational period; remove unnecessary personal content.
- Billing records: retain as required for accounting/legal obligations; do not couple deletion to learning records blindly.
- Security/audit logs: retain for a defined security investigation window.

Deletion requests must be identity-verified and assessed against controller obligations before destructive action. A future automated retention job should use per-record policy constants and audit every deletion batch.
